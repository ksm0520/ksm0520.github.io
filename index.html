Next.js 렌더링과 검색 상태

SSG · ISR · Dynamic SSR

193.7 → 81.6 ms초기 도시 목록 표시 중앙값 · 57.9% 단축

문제

도시 목록은 브라우저가 API 응답을 받은 뒤에야 표시됐고, 새로고침하면 검색 조건이 사라졌습니다.

  1. 01

    접근

    소개는 SSG, 공통 목록은 1시간 ISR, 요청마다 달라지는 검색은 Dynamic SSR로 나눴습니다. 지도와 일정 화면은 CSR을 유지했습니다.

  2. 02

    구현

    국가·도시 데이터를 서버에서 병렬 조회해 전달하고, 검색 조건은 URL에 저장했습니다.

  3. 03

    결과

    목록 데이터 요청 2회 → 0회, 화면 전환 전송량 36.4% 감소. 검색 조건 공유·새로고침·뒤로가기를 지원합니다.

목록 표시: 로컬 production / Docker 백엔드 / 406×661 / 캐시·throttling 없음 / 5회 중앙값. SSR 검색 표시는 138 → 216ms.

    공유 상태 충돌 완화

    결과

TanStack Query 갱신 정책

문제

  1. 01

    접근

    queryOptions로 키·요청 함수·staleTime을 통일했습니다.

  2. 02

    구현

    검색 중 이전 목록을 유지하고, 삭제는 캐시에서 먼저 반영한 뒤 실패하면 복구하도록 했습니다.

  3. 03

    결과

    검색 중 목록이 유지되고, 저장·삭제 후에는 해당 여행의 장소만 다시 조회합니다.

상세 진입 클릭 시 prefetch 요청은 존재하지만, 현재 상세 페이지는 API를 별도로 조회합니다.

Three.js 온보딩 최적화

488 → 148 ms약 3초 Performance 기록 내 스크립트 실행 합계

문제

온보딩 애니메이션이 끊기는 원인을 찾기 위해 DevTools Performance로 프레임별 실행 시간을 살폈습니다.

  1. 01

    초기 실행 분리

    Three.js를 동적으로 로딩하고 화면 폭에 따라 파티클 수를 8,000개 또는 5,000개로 조절했습니다.

  2. 02

    반복 작업 줄이기

    30fps를 목표로 프레임을 건너뛰고 deltaTime으로 속도를 보정했습니다. 파티클 반복문 안에서는 Vector3를 재사용했습니다.

  3. 03

    결과

    약 3초 기록에서 스크립트 실행 합계가 488ms에서 148ms로 줄었습니다.

측정값은 스크립트 실행 합계입니다. animate 호출마다 생성되는 객체는 남아 있습니다.
